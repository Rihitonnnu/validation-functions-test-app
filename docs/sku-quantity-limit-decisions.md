# SKU ごとの購入制限: 検討まとめ

`cart-quantity-limit`(カート全体で合計 30 点まで)とは別に、**SKU ごとに異なる購入上限**をかける仕組みを検討した記録です。実装の詳細は [sku-quantity-limit.md](./sku-quantity-limit.md) を参照してください。

## 結論

- `cart-quantity-limit` とは独立した Validation Function **`sku-quantity-limit`** を作る。
- 上限値は**バリアントのマーチャント所有メタフィールド `custom.max_quantity`**(整数、最小値 1)に保存する。
- **SKU 文字列ごと**に数量を合算し、上限を超えたらチェックアウトをブロックする。

## 1. 上限値をどこに保存するか

| 案 | 評価 | 理由 |
| --- | --- | --- |
| **バリアントのメタフィールド(マーチャント所有)** | ✅ 採用 | 値がカートの各行に付いて届くので、SKU 数に上限がない。管理画面・一括エディタ・ほかのアプリから編集できる |
| Validation 本体に JSON で `{SKU: 上限}` を 1 つ持たせる | ❌ | Shopify 公式チュートリアルの構成で、設定を一元管理できる。ただし Function が読めるメタフィールドは **10,000 バイトまで**(約 500 SKU が目安)。商品が約 300 点で SKU はさらに多いため、上限に達する。超えると `null` が返り、**全 SKU の制限が黙って外れる** |
| 商品のメタフィールド + バリアントで上書き | △ 見送り | 入力の手間は減るが、ロジックと入力クエリが複雑になる。今後の拡張候補 |
| コレクションごとの段階制限 | ❌ | 「限定コレクションは 1 点まで」のような運用はできるが、SKU ごとの細かい値は設定できない |
| アプリ所有のメタオブジェクト | ❌ | Function からは固定のハンドルでしか引けない。JSON 案と同じ制約になる |
| B2B の数量ルール | ❌ | B2B カタログ専用で、一般の購入者には使えない |

## 2. アプリ所有か、マーチャント所有か

|  | アプリ所有(`$app`、TOML で定義) | マーチャント所有(`custom`) |
| --- | --- | --- |
| 管理画面での値の編集 | できる(`merchant_read_write` を指定) | できる |
| ほかのアプリからの読み書き | **できない** | できる |
| 定義の変更・削除 | このアプリだけ | マーチャントとすべてのアプリ |
| 定義の作り方 | `shopify.app.toml`(デプロイで自動作成) | 管理画面か `metafieldDefinitionCreate`(ストアごとに 1 回) |

→ CSV 一括入稿アプリや PIM/ERP 連携からも上限値を扱えるようにするため、**マーチャント所有**にした。

**引き受けたリスク**: 定義が削除されたり、キーや型が変えられたりすると、Function は値を読めず**すべて「制限なし」**になる(エラーは出ない)。ドキュメントに注意を書いた。値が読めなくても Function はクラッシュしない。

## 3. 判定ルールの細かい決定

| 論点 | 決定 | 理由 |
| --- | --- | --- |
| 集計の単位 | SKU 文字列(複数の行・バリアントにまたがれば合算) | 「SKU ごと」という要件にそのまま合う |
| SKU が空のバリアント | バリアント ID で集計する | 上限が設定されているなら必ず効かせるため |
| 同じ SKU で上限が異なる | 小さいほうを使う | 厳しい側に倒す |
| 上限が未設定・数値でない・1 未満 | 制限なし | 設定ミスでチェックアウトが止まるのを避ける |
| 上限ちょうど | 許可(超えたらブロック) | `cart-quantity-limit` と同じ |
| エラーの表示位置 | カート全体(`$.cart`) | Validation API ではカートの行をエラーの表示位置に指定できない。どの商品かはメッセージの商品名で伝える |
| エラーの件数・順序 | 違反した SKU ごとに 1 件、カートの行順 | どの商品を減らせばよいかがわかる |

## 4. 今回は対象外としたこと

- 商品単位のデフォルト上限(バリアントで上書き)
- 上限が設定されている SKU の一覧・編集画面(現状は一括エディタか Admin API で確認する)
- 過去の注文を含めた「1 人あたり累計◯点まで」の制限(注文履歴が必要で、Function 単体ではできない)
